# Agent 交付审核以文件版本审核为最小单位

Agent-managed task 的状态是 Server 生命周期投影，不能由用户在看板或任务详情中自由改写；用户只能通过交给智能体、审核文件版本、退回修改、验收交付、取消或关闭等具名动作推进。`in_review` 表示一次 Task delivery 等待人类处理，其中包含包内文件版本的审核覆盖和 Task 交付验收两个门槛；文件包只是冻结交付容器和批量操作入口，不拥有独立审核版本或替代包内文件版本审核。

文件版本审核权与 Task 交付验收权在模型上保持分离，因为前者证明文件版本可用，后者证明当前任务目标完成。首版产品体验可以默认让任务发起人或项目负责人同时拥有两类动作，避免要求小团队配置两套角色；但 Server 仍必须把文件审核和交付验收写成不同事实。

首版 UI 中，文件页保留为文件包和文件资产视图，展示版本、来源、审核态、最终版和引用入口；逐文件审核放在预览/编辑浮窗里完成，因为审核者必须看到文件内容和当前版本后才能通过、要求修改、拒绝或保存并通过。

文件审核、最终版设置和 Task 验收是三类独立事实：批量审核文件包必须落成多条文件版本审核记录，最终版只移动文件集合的定稿指针，Task `done` 只能由合法交付验收产生。`done`、`cancelled` 和 `closed` 都是终态，不 reopen；需要继续工作时创建带 lineage 的 follow-up、continuation 或 replacement task。退回修改只写审核和退回事实，不自动重跑 Agent，后续执行必须由用户在讨论串中显式选择 Agent 和冻结输入版本。
